# Audit of Mathematics Skills Inventory — рівень 1–3 років навчання

> **Статус:** методичний аудит v0.1, 27.10.2026. Не є сертифікацією відповідності програмам, математичним тестом покриття чи оновленням чинного списку Skill. Базовий документ: [skills-inventory.md](./skills-inventory.md), **259 кандидатів**.

## Короткий висновок

Початковий інвентар **добре охоплює базове арифметичне ядро**: лічбу, позиційність до 1000, додавання й віднімання, таблиці множення й ділення, задачі, первинні дроби, вимірювання, геометрію та просту статистику. Проте це **не повна міжпрограмна карта** для 1–3 років. Прогалини концентруються в **елементарній ймовірності, трансформаціях і просторових маршрутах, глибших уявленнях про дроби, площі та графіках виміряних величин**.

Жодного відсотка «покриття міжнародних програм» не встановлено: для достовірного відсотка потрібна окрема трасувальна матриця **кожен нормативний результат → один/кілька Skill → підтверджена еквівалентність**. Кількість Skill сама по собі не є метрикою повноти.

## D. Що варто зробити перед кодогенерацією

1. **Не змінювати чинні 259 ID мовчки.** Спочатку узгодити уточнення й окремо затвердити нові.
2. **Розділити «Core» і «Expansion».** «Core» — широко застосовні основи; «Expansion» — компетенції, які зустрічаються в окремих системах або потребують поглиблення. Ця класифікація може жити лише в редакційному документі, не в `SkillDefinition`.
3. **Зафіксувати семантичну гранулярність.** Окремий Skill потрібен, якщо має самостійну діагностику і сенс для рекомендацій; інакше це конкретний випадок питання/генератора.
4. **Не зберігати «клас», «програму», «передумови» чи «тип перевірки» у Skill**: майбутня технічна сутність залишається `id` + `name: Record<Locale,string>` + репозиторний `fileLocation` із builder/indexer.
5. **Для кількісного coverage-звіту** створити окрему матрицю нормативних learning outcomes для обраної системи з позначками `covered / partial / missing / not-in-scope`, ID джерела та примітками. Це задача наступного методичного раунду, а не припущення з кількості рядків.
6. **Перевірити 26 запропонованих ID** на дублювання з інвентарем; після погодження додати до `skills-inventory.md` окремим commit, і тільки потім масово генерувати файли.
